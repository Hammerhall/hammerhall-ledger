# Код из статей

Здесь — то, что нужно, чтобы собрать пример статьи: `pom.xml` и файлы,
которые кладёт start.spring.io. Сам код берётся из раздела
«Пример целиком» статьи — так код в статье и код, который собирается,
не могут разойтись.

Каждый прогон [GitHub Actions](../.github/workflows/examples.yml):

1. раскладывает примеры из статей в `build/examples/`;
2. собирает каждый на Java 25 — `mvn verify`, с тестами;
3. проверяет, что обещает статья словами: какой текст печатает
   программа, где и с какой ошибкой она падает (`checks.sh` рядом
   с примером).

Красный прогон — статья на сайт не выходит.

## Собрать у себя

Нужны JDK 25, Maven и Python 3.

```bash
python3 tools/extract_examples.py
cd build/examples/articles/01-why-spring
mvn verify
```

Проверки статьи целиком — из корня репозитория:

```bash
bash tools/run_examples.sh                      # все разложенные примеры
bash tools/run_examples.sh articles/06-stand    # только один — так их гоняет CI
```

Пример стоит на прошлом (`base`), но в его задаче CI собирает и проверяет
только его самого: прошлые лишь раскладываются. Красный пример красит
одну задачу, а не все, что идут после него.

## Как устроена папка примера

| файл | что |
|---|---|
| `example.json` | из какой статьи брать код; на каком примере стоит этот (`base`) и что из него убрать (`delete`) |
| `pom.xml` | зависимости — как в статье; нет файла — берётся `pom.xml` того примера, на котором стоит этот (`base`) |
| `src/…` | только то, чего нет в статье: файлы от start.spring.io |
| `checks.sh` | что статья обещает словами — проверяется запуском |
